Serve TanStack Start apps with locale twins (experimental). Locale twin apps import GT from `gt-tanstack-start/experimental`, which re-exports `gt-tanstack-start` with the locale twin versions from `gt-react/experimental`, and register `gtTanstackStart()` from `gt-tanstack-start/experimental/plugin/vite`, which runs `@generaltranslation/compiler/experimental` (enable it with `experimentalCompilerOptions: { type: 'babel' }`; it also accepts the compiler's `localeTwins` build options) and inserts JSX from `gt-tanstack-start/experimental`.

The server export `createLocaleTwinAssets({ manifest })` from `gt-tanstack-start/experimental` points the document's entry script, module preloads, early hints, and the client router manifest at the request locale's twins. Pass it to `createStartHandler({ transformAssets })` in your server entry (`transformAssetUrls` on TanStack Start versions before `transformAssets`), with `manifest` imported from `virtual:gt-locale-twins-manifest` (types: `/// <reference types="@generaltranslation/compiler/experimental/locale-twins-manifest" />`). The locale is resolved exactly as for SSR (path locale with `localeRouting`, then the locale cookie, then `Accept-Language`, then the default; the default locale's twins when the enable-i18n cookie is `false`), the transform is created per request (`cache: false`), and it needs no file system access, so it runs on edge runtimes. A `null` manifest (dev) leaves URLs unchanged; a manifest with an unknown format version is rejected.

With `experimental.splitting: 'locale-twins'`, the experimental `setupRouterGTIntegration` still loads the request locale's translations on the server before rendering, but sends an empty translations snapshot to the client in production (`vite dev`, which serves no twins, keeps it, and so does an app with a dictionary), and it marks SSR documents, error documents such as a 404 included, with `Vary: Cookie, Accept-Language` and, unless a route or the request sets its own, `Cache-Control: private, no-cache`. The experimental `getGT()`/`getMessages()` resolve from the twins, and `t()` translates into the request locale during server rendering (the experimental server setup gives the runtime the request-scoped store). Locale twin clients never call the translation loader.
