'@generaltranslation/paraglide-js': patch
---

Rewrite the usage analysis of `paraglide-context` and `collectContext()` in Rust, as a Node addon that reads, parses and analyzes a project on every core. A project of 10,000 source files is analyzed in under a second instead of about four, and one of 100,000 files in about six seconds within 5 GB of memory. The metadata files are unchanged. When several files pass different messages to the same parameter, their usages are now reported in the same order on every run. A language that claims scripts with `detect` can name the texts its files contain in `mayContain`, so that other scripts are not read in JavaScript.

The analysis also writes the metadata files itself, from the code and usages it keeps, as the TypeScript implementation wrote them: a project's source code no longer passes through JavaScript, and a metadata file is no longer limited by the length of a JavaScript string. A file whose content did not change is not written.

Every built-in language is now read by the analysis itself, in Rust, without the framework's tooling: Vue (with Pug templates), VitePress Markdown, Svelte 3 to 5, Astro, MDX, Marko, Ember's template tags, Angular components, templates and pages, and Analog. A project no longer needs `vue-tsc`, `svelte-check`, `@astrojs/check`, `@mdx-js/language-service`, `@marko/language-tools`, `@glint/ember-tsc` or `@angular/compiler` installed, and they are no longer optional peer dependencies. A template expression that does not parse leaves out only itself, not the file. A language passed in `languages` still runs in JavaScript. The project's files are listed by the analysis too, honoring `.gitignore` as git does, and `PARAGLIDE_CONTEXT_THREADS` sets how many threads work besides the main one, in digits. On a project of 2,000 files of 10,000 lines in every supported language, a run takes about 1 second instead of 18, and its metadata files are unchanged.
