Rewrite the usage analysis of `paraglide-context` and `collectContext()` in Rust, as a Node addon that reads, parses and analyzes a project on every core. A project of 10,000 source files is analyzed in under a second instead of about four, and one of 100,000 files in about six seconds within 5 GB of memory. The metadata files are unchanged. When several files pass different messages to the same parameter, their usages are now reported in the same order on every run. A language that claims scripts with `detect` can name the texts its files contain in `mayContain`, so that other scripts are not read in JavaScript.

The analysis also writes the metadata files itself, from the code and usages it keeps, as the TypeScript implementation wrote them: a project's source code no longer passes through JavaScript, and a metadata file is no longer limited by the length of a JavaScript string. A file whose content did not change is not written. The tooling of component files (Vue, Svelte, Astro, MDX, Marko, Ember, Analog, Angular templates) runs on worker threads when a project has many; `PARAGLIDE_CONTEXT_THREADS` sets how many threads are used, `0` for the main thread only. The files are read and parsed while the others are still being listed, and the analysis takes less memory: its syntax trees are smaller, most variables' bindings are kept in a few bytes, and the trees are given back as soon as the usages are found.
