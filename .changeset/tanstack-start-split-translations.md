---
'gt-tanstack-start': minor
---

Add the experimental `experimentalSplitTranslations` option to server-rendered TanStack Start apps: `gtTanstackStart({ experimentalCompilerOptions: { experimentalSplitTranslations: {} } })`, or the `GT_SPLIT_TRANSLATIONS` environment variable. A production build then writes the translations of each client chunk into small files next to it, and a page gets only the translations of the code it loads. On a first visit the server sends them with the page it renders, for the routes the request matched and the client components its server components render, so the browser requests no translations file before it hydrates. A navigation or a hover preload requests the files of its route with the route's chunks. The server still renders from each locale's whole translations file, and the browser no longer bundles those files. The keys of the option are the compiler's (`by`, `minifyHashes`, `naming`, `requestCost`, `previous`), with one other default: `requestCost` is 2048, as a server-rendered page waits for no file before it hydrates.

Setting the option turns the GT compiler on: `experimentalCompilerOptions.type` now defaults to `'babel'` when the split is on, and stays `'none'` otherwise, so an app that does not use the split builds as before. `type: 'none'` with the split on fails the build.

Messages the build cannot tie to a client chunk, such as `msg()` and dictionary entries, travel with every page, and so does every `msg()` in code that only the server runs, which can reach the browser as data. A build that splits takes its translations from `files.gt.output` alone: it fails with a custom `loadTranslations` (`src/loadTranslations.*` or `loadTranslationsPath`), which could return other translations than the files a navigation loads. Static prerendering, a prerendered SPA shell, `ssr: false` and `data-only` routes, locale routing, a `base` other than `/` and assets that `transformAssets` moves to another origin are supported.
