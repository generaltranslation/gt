feat(compiler): generate locale twins in Vite builds

- With `files.gt.splitting: 'locale-twins'` (or the `splitting` plugin option), `vite build` generates locale twins after the client environment is written: it reads `[locale].json` from `files.gt.output` (relative to the working directory), writes a twin of every twinned chunk per locale and the twin manifest `gt-locale-twins.json` at the client output root, writes the build report to `node_modules/.cache/gt/gt-locale-twins-report.json` under the Vite root (out of the public output; it lists twinned and shared files, sizes, missing translations and unattributed entries), and logs a summary. Server environments and `vite dev` are left as they are: in `vite dev` the compiler output is the same as without locale twins. Locale twins need Vite: with webpack, Rspack, esbuild or plain Rollup the plugin warns once and skips them.
- The client build gets a default `vendor` chunk (Vite 8 `codeSplitting.groups`, Vite 7 `manualChunks`, added in the `outputOptions` hook) for library code, excluding library modules that import the app, so library code is not copied per locale. This also holds for TanStack Start, whose client entry is library code that imports the app. A user's own chunking config (or `output.preserveModules`) is kept, with a warning. Opt out with `localeTwins.vendorChunk: false`. Vite 8's `build.chunkImportMap` is not supported with locale twins and fails the build. In `vite build --watch`, editing a translation file regenerates the twins.
- Server builds can import the client manifest from `virtual:gt-locale-twins-manifest` (`export const manifest`, `null` in dev, even when an earlier build left a manifest in the outDir, or when locale twins are off). Types: `/// <reference types="@generaltranslation/compiler/locale-twins-manifest" />`.
- Diagnostics for missing translation files, missing translations (`localeTwins.missingTranslations: 'error'` fails the build), a large output multiplier, unfilled placeholders in files served as built, `compileTimeHash: false`, a server build without the client manifest, a non-Vite bundler, and a dev-mode notice.
