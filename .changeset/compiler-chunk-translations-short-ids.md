Add the experimental `experimentalChunkTranslationsShortIds` option (or the `GT_CHUNK_TRANSLATIONS_SHORT_IDS` environment variable) to builds with `experimentalChunkTranslations`. The call sites such a build splits by chunk or by module, `<T>` and `t` templates from `gt-react`, then pass a short id in place of their hash of 16 characters, and the translation files of chunks are keyed by the same id, which makes the JavaScript and those files smaller. `true` is 8 characters, the first 48 bits of the hash in base64url; a number from 1 to 10 is that many characters. The id follows from the hash alone, so it is the same in every build.

The hash of a message does not change anywhere else: the translation files at `files.gt.output`, the unsplit file, `msg` and every call site whose hash is computed at runtime keep it, and a message that a `t` template and a `msg` share is found under both. A `t` template whose hash is computed when it runs, because its options or a value are not written at the call, reads by hash as well: the build keeps every compiled message with the same text and structure in the unsplit file under its hash too, whatever its options and the names of its values. It warns of the modules whose call sites it cannot say that of, as with `derive()`; there, a message that a compiled call site also reads renders its source text. The build fails, and names both messages, when two messages of the app or of its translation files would share an id; with 8 characters that happens to one project of 65,000 messages in about 133,000. It also fails without `experimentalChunkTranslations`, and with `_tagIds`, which writes the id of a `<T>` into the page for tools that read it as the hash. Off by default, and a build without the option is unchanged.
